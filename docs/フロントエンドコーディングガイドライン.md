# N7B フロントエンドコーディングガイドライン

Nuxt 4 + TypeScript + Nuxt UI v4 でのフロントエンド実装ルール。スタイリングや SFC の基本規約は @../CLAUDE.md を参照。

---

## 1. メディア要素の使用ルール

**原則**: 画像・動画は Nuxt の専用コンポーネントを必ず使う。素の `<img>` / `<picture>` / `<video>` タグは禁止。

### 必須ルール

1. **画像は `<NuxtImg>` または `<NuxtPicture>` を使う**
   - 単一フォーマット配信なら `<NuxtImg>`、`<source>` で AVIF/WebP/JPEG をフォールバックさせるなら `<NuxtPicture>`
   - 素の `<img>` タグは禁止 (Vercel Image Optimization が効かず、自動 AVIF/WebP 変換・遅延読み込み・寸法管理が失われる)
   - `width` / `height` 属性は必須 (詳細は §2 CLS 防止)
   - ファーストビュー以外は `loading="lazy"`、ヒーロー画像など LCP 候補には `preload`
   - `alt` 属性は必ず指定 (装飾画像は `alt=""`)
2. **動画は IframeYouTube/Vimeo 等の埋め込みか `<video>` を使うが、寸法を必ず固定する**
   - Nuxt には動画専用コンポーネントがないため、`<video>` を使う場合も `width` / `height` または `aspect-ratio` を必ず指定する
   - 外部動画 (YouTube 等) は `<iframe>` に寸法を指定し、`loading="lazy"` を付ける
3. **画像比率は @デザインガイドライン.md §7.2 のサイズに従う**
   - 商品 `1:1`、コンテンツカテゴリ `4:3`、ヒーロー `16:9` (PC) / `4:3` (SP)、記事ヒーロー `16:9`、OGP `1.91:1`

---

## 2. レイアウトシフト (CLS) 防止

**原則**: 要素が描画された後に位置や寸法が変わるコードを書かない。サイズが事後に確定する要素は、確定前にスペースを必ず予約する。

### 必須ルール

1. **画像・動画・iframe には必ず寸法を指定する**
   - `<NuxtImg>` / `<NuxtPicture>` には `width` / `height` を必須属性として渡す。比率が動的なら `aspect-ratio` (Tailwind の `aspect-square` / `aspect-[4/3]` 等) でコンテナを固定する
   - 商品画像 (`aspect-square`)、コンテンツカテゴリ (`aspect-[4/3]`)、ヒーロー (`16/9` または `4/3`) は @デザインガイドライン.md §7.2 のサイズに従う
2. **非同期データの差し込み箇所は空のままにしない**
   - `useAsyncData` / `useFetch` の `pending` 中は `<USkeleton>` で最終形と同じ寸法のプレースホルダを出す。`pending` を `v-if` で隠してから差し込むのは禁止 (差し込み時にシフトする)
   - Lazy コンポーネント (`<LazyXxx>`) は `<template #fallback>` を必ず書く
3. **動的テキストは高さを先に確保する**
   - 文字数が API レスポンスで決まる箇所 (商品名・お知らせタイトル等) は、最大行数を `line-clamp-N` で固定し、コンテナに `min-h-[Npx]` を指定する。レスポンス到着で行数が変わって他要素が押し下げられる状況を作らない
   - チャットスレッドや可変長カードなど、レンダリング前に高さが必要な箇所では [pretext](https://github.com/chenglou/pretext) のような事前計測を検討する (現状は採用していないが、必要が出たら導入候補)
4. **後から差し込まれる要素は overlay / fixed で配置する**
   - 通知バー・お知らせバナー・Cookie 同意などは `position: fixed` または `position: absolute` で既存コンテンツの上に重ねる。本文を押し下げる実装は禁止
   - どうしても押し下げる場合は、初期描画時から領域を予約しておく
5. **アニメーションは `transform` / `opacity` のみ使用**
   - `width` / `height` / `margin` / `top` / `left` / `padding` のトランジションは禁止 (リフローが走る)。`translate` / `scale` / `opacity` で表現する
   - ホバー時のカード浮き上がりは `translate-y-[-2px]` (@デザインガイドライン.md §9.2 に準拠)
6. **Web フォントの読み込みで文字サイズを変えない**
   - `@nuxt/fonts` の `fallback` と `size-adjust` 設定で本文フォントのメトリクスを揃える。新規フォント追加時は `font-display: swap` だけでなく `size-adjust` / `ascent-override` も検証する
7. **スクロールバーの出現/消失でシフトさせない**
   - モーダル開閉でスクロールバーが消えるとレイアウトがズレる。`scrollbar-gutter: stable` を `html` に指定済み (なければ追加)

### チェック方法

- Nuxt DevTools の `@nuxt/hints` パネルで `webVitals` の CLS 警告を確認 (閾値は CLS < 0.1)
- Chrome DevTools の Performance タブで "Layout Shift" 帯を確認
- 本番デプロイ後は Vercel Analytics の CLS スコアを定期的に確認
