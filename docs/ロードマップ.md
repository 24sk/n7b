
### 全体方針

立ち上げ目標を「**最短でEC機能まで動く状態を作り、その後段階的に拡張**」とします。理由は、商品が売れる体験を早く作ることで、N7Bが「ものづくり拠点」として動き出している実感が得られるからです。記事やWorksは後からでも追加できますが、ECは「立ち上がっている感」を作る核になります。

並行作業の前提を置くと、N7Bは「平日夜＋週末」のペースで進めると現実的です。週あたり10〜15時間程度を想定し、各フェーズを2〜4週間で区切ります。

### ロードマップ全体像

```
Phase 0: 準備・環境構築        (1週間)   ─ 基盤整備
   ↓
Phase 1: 静的サイト公開        (2〜3週間) ─ "存在する"状態を作る
   ↓
Phase 2: EC機能リリース        (3〜4週間) ─ 売れる状態を作る
   ↓
Phase 3: コンテンツ運用基盤    (2〜3週間) ─ "動いている"状態を作る
   ↓
Phase 4: 拡張機能              (継続)    ─ 必要に応じて
```

おおよそ **8〜11週間（2〜3ヶ月）でPhase 3完了** が現実的な目標です。Phase 4は会員機能やWorks充実など、必要が出てから着手します。

### Phase 0: 準備・環境構築（1週間）

サイト実装の前に整える基盤です。地味ですが、ここを丁寧にやると後が楽になります。

**ドメイン取得** `nango7base.jp` をお名前.com / Cloudflare Registrar / Google Domains などで取得。`.jp` は年間 3,000〜4,000円程度。Cloudflare Registrar が最安かつDNS管理も統合できるので推奨です。

**GitHubリポジトリ作成** プライベートリポジトリで `n7b` を作成。READMEとライセンス（個人プロジェクトならMITまたは未指定）を設定。`.gitignore` は Node 用テンプレートをベースに。

**Vercelプロジェクト作成** 既存のVercel Proアカウントで `n7b` プロジェクトを作成し、GitHubリポジトリと連携。カスタムドメインを設定。

**Stripe アカウント設定** N7B用のStripeアカウントを開設、もしくは既存アカウントの中で「N7B」用の商品グループを整理。テストモードと本番モードの切り替えを確認。日本円通貨設定、Konbini決済の有効化を含めて初期設定。本番モードへの切り替えには事業者情報の登録が必要なので、これも済ませておく。

**Resend アカウント設定** 無料アカウント作成、独自ドメイン認証(SPF / DKIM / DMARC)を Cloudflare DNS に設定。送信元アドレス `noreply@nango7base.jp` `contact@nango7base.jp` を準備。

**Notion ワークスペース準備** 個人用Notionワークスペースに「N7B」セクションを作成、お問い合わせ管理データベースとお知らせ管理データベースを準備。Notion Integration を作成しAPIトークン発行。

**Sentry プロジェクト作成** 無料プランで `n7b` プロジェクトを作成、DSNを取得。

なお、お問い合わせ受付・Stripe Webhook 処理・注文通知などの自動化はコストと初期スケールを考慮し、外部ワークフローツール（n8n等）を使わずに Nuxt の server route 上で直接実装する方針とする。

**完了条件** ドメインが取得され、Vercel Pro に空のNuxt 4プロジェクトがデプロイされて「Welcome to Nuxt」が表示される状態。全外部サービスのAPIキーが手元に揃い、`.env.example` に列挙されている状態。

### Phase 1: 静的サイト公開（2〜3週間）

カンプで作ったデザインを実装し、商品機能なしで公開するフェーズです。「ものづくりの拠点ができたよ」と告知できる状態を作ります。

#### 週単位の進め方

**Week 1: 基盤実装** Nuxt 4プロジェクト初期化、TypeScript設定、Tailwind CSS導入、Nuxt UI または独自コンポーネント方針の確定。レイアウト（Header / Footer）実装、フォント設定（日本語フォントの選定: Noto Sans JP または LINE Seed JP など）、ブランドカラー（ティール系）のTailwind設定。

**Week 2: 主要ページ実装** トップページ（ヒーロー + 拠点で生まれたもの + 4カテゴリ + お知らせ + メルマガ + SNS）、Aboutページ、Contactページ。この時点では商品とお知らせはハードコードまたはJSONで仮実装。

**Week 3: コンテンツ運用とお問い合わせ** Nuxt Content v3導入、お知らせ（news）コレクション設計、お知らせ一覧・詳細ページ実装。お問い合わせフォーム + Nuxt server route（`server/api/contact.post.ts`）で Notion 登録と Resend メール送信を直接処理 + Cloudflare Turnstile によるスパム対策。Sentry連携。レスポンシブ対応の最終確認。

#### このフェーズで完成するもの

トップページ、About、Contact、お知らせ一覧・詳細、メルマガ登録（フォームのみ、購読リスト管理は次フェーズでも可）が動作。商品は「Coming Soon」または準仮表示。

#### 完了条件

`nango7base.jp` にアクセスして全ページが表示される。お問い合わせを送信すると Notion にレコードが追加され、Tsuyoshiさんのメールに通知が届く。Lighthouseスコアで Performance / Accessibility / Best Practices / SEO がそれぞれ 85点以上。

#### Phase 1で発生しがちな落とし穴

日本語フォントの読み込み速度に注意。Noto Sans JPをフル読み込みすると重いので、`font-display: swap` + サブセット化（next/font相当のUnplugin Fonts）を検討。SSGとSSRの使い分けで迷いがちですが、最初は全ページSSRで統一して、Phase 3以降で必要に応じてISRやSSGに切り替えるのが安全です。

### Phase 2: EC機能リリース（3〜4週間）

Stripe を使った商品販売機能を実装するフェーズです。N7Bが「売る場所」として動き出します。

#### 週単位の進め方

**Week 1: Stripe商品設計と一覧ページ** Stripe Dashboardで商品マスタを登録（マグカップ、ランタン、ノート、ステッカー、Tシャツ）。商品メタデータの設計（カテゴリ、制作ストーリーリンクなど）。Nuxt server route で Stripe Products API から商品取得（ISR 10分キャッシュ）。商品一覧ページ実装、商品詳細ページ実装。

**Week 2: カート機能** クライアント側カート状態管理（Pinia または useState + localStorage）。カートに入れる、数量変更、削除、合計金額計算。カートアイコンのバッジ表示（カート内アイテム数）。カートページ実装。

**Week 3: Checkout統合** Stripe Checkout Session作成API、リダイレクト型決済導線、Checkout成功/キャンセルページ実装。配送先住所収集、コンビニ決済対応、消費税対応(Stripe Tax または商品価格に含める方式)。Stripe Webhook受信実装（`server/api/webhooks/stripe.post.ts` で署名検証 + 後続処理を直接実装）。

**Week 4: 注文管理と運用整備** Stripe Webhook ハンドラ内で注文通知フローを構築（Notion 注文管理 DB 登録、顧客への注文確認メール送信（Resend）、Tsuyoshi さんへの注文通知（メール or Slack Incoming Webhook 呼び出し））。返品・キャンセル運用ルールの策定。特定商取引法に基づく表記ページ作成、プライバシーポリシー、利用規約の作成。本番Stripe切り替え、本番決済テスト（少額の自己決済で動作確認）。

#### このフェーズで完成するもの

5商品が販売可能、カート→Checkout→決済完了→注文確認メールが届くまでの全フロー。Notionで注文履歴が管理できる状態。返品・キャンセルポリシー含む法的ページ。

#### 完了条件

実際にカードで購入できて、商品確定→Stripeに支払い記録→Notionに注文情報→顧客と運営者にメール通知、までが自動化されている。本番モードでテスト購入が成功している。

#### Phase 2で気をつけるべき重要点

**特定商取引法表記** 日本でEC運営する以上、特定商取引法に基づく表記は必須です。事業者名、住所、電話番号、返品ポリシーなどを記載する必要があります。住所は自宅でも可能ですが、開示したくない場合はバーチャルオフィスを検討。

**消費税の扱い** Tsuyoshiさんが課税事業者か免税事業者かで対応が変わります。デザインカンプの価格表示が「(税込)」になっているので内税方式で進める想定です。インボイス制度対応の必要性も初期から考えておく。

**返品・キャンセル運用** 特定商取引法上、明示が必要。Stripeでは部分返金・全額返金が管理画面から可能なので、Stripe Webhook ハンドラで `charge.refunded` 等の返金イベントも受信し、Notion 注文 DB のステータスを更新するようにしておくと運用が楽になります。

**在庫管理の方針** Stripe単体では在庫管理機能が弱いため、初期はNotionで手動管理する方針が現実的。完売したらStripeダッシュボードで「アーカイブ」する運用。月10件程度の販売規模ならこれで十分です。

### Phase 3: コンテンツ運用基盤（2〜3週間）

サイトを「動いている拠点」として見せるためのコンテンツ運用基盤を整えるフェーズです。

#### 週単位の進め方

**Week 1: Journal（記事）機能** Nuxt Content v3でjournalコレクション設計、frontmatter設計（タイトル、説明、公開日、カテゴリ、タグ、ヒーロー画像）、記事一覧・詳細ページ実装、カテゴリ別フィルタリング、関連記事の表示。

**Week 2: 制作ストーリー機能** 商品ごとの制作ストーリーをNuxt Contentで管理、Stripe商品メタデータと連携、商品詳細ページから制作ストーリーへのリンク導線、制作ストーリーから購入導線への動線。

**Week 3: メルマガ機能と運用整備** メルマガ購読者管理（Resend Audiences または Vercel KV で購読者リスト管理）、購読登録・配信解除フロー、メルマガ配信用テンプレート設計、最初の配信。SEO最終調整、OGP画像生成、構造化データ（JSON-LD）追加、サイトマップ・robots.txt生成。

#### このフェーズで完成するもの

記事を書いてGit Pushすれば公開できる状態、商品詳細から制作ストーリーへの導線、メルマガ購読者管理。SEO対応完了。

#### 完了条件

最初の記事3本以上が公開されている、各商品に制作ストーリーが紐づいている、メルマガ登録〜配信解除のフローが動作する、検索エンジンに正しくインデックスされている。

### Phase 4: 拡張機能（必要に応じて継続）

Phase 3までで N7B サイトとしては自走できる状態になります。Phase 4以降は「ニーズが顕在化してから着手」が原則です。早期に着手しても、需要がない機能を作ってしまう可能性が高いからです。

#### 拡張候補

**Worksセクション充実** BELTAでの業務以外の個人開発（cmux、波予測リサーチ、OpenMythos関連など）を公開できる状態に。Notion API連携、GitLab/GitHubメタデータ取得自動化。優先度: 制作実績が3件以上溜まってから。

**Base Camp（有料コンテンツ）** Supabase Auth + Stripe Subscription による会員制機能。Tsuyoshiさんのノウハウ（Claude Code活用、AI駆動開発、自動化など）を有料コンテンツとして提供するなら。優先度: 無料記事のファンが増えてから。

**Community機能** コメント機能、Discord連携、メンバー間交流。優先度: 月間訪問者が500人を超えてから。

**ワークショップ・イベント予約** 日程管理、参加申込、Stripe決済連携。優先度: オフラインイベントを企画する段階で。

**多言語化** 英語対応など。優先度: 海外からの問い合わせや関心が見えてから。

#### 各拡張の判断基準

新機能を入れるかどうかは「データを見てから判断」を徹底します。Vercel Analyticsで訪問者の行動パターン、Stripeで売上推移、Resendで開封率を継続的に観察し、ボトルネックや明確なニーズが見えた箇所から着手するのが、個人運営での消耗を防ぐコツです。
