## この記事で渡すこと

Notion の社内システム一覧を標準フォーマットで揃えたい、という運用課題に Claude Code + Notion MCP で挑んだ記録です。結論を先に言うと、**「ネイティブテンプレート」と「DB 内の通常レコード」を API 上で取り違えやすい**こと、そして **`insert_content` と `replace_content` で Markdown の解釈が変わる**ことの 2 点が当日の最大のつまずきでした。同じ構成で社内ドキュメントを整備したい人向けに、踏み抜いた地雷だけをまとめます。

## やりたかったこと

社内には 28 個の稼働システムが Notion DB に並んでいて、各ページの中身がバラバラでした。N7B は「読み手別 (意思決定者 / 開発者 / 運用者) に章を分けた 1 ページ完結型テンプレート」を設計し、**Claude Code 経由で Notion に流し込む**方針を取りました。

イメージとしては、ラーメン屋のメニュー表を全店舗で同じレイアウトに揃える作業に近いです。器の形 (DB プロパティ) と、品書きの順序 (§0 TL;DR → §1 概要 → §2 構成 …) を統一すれば、初めて見る人でもどこに何が書いてあるか迷わずに済む、という発想です。

## つまずき 1: ネイティブテンプレートは API から「作れない」

まず最初に作ったのは、DB 内に 1 件のページとして置いた「【コピー用】テンプレート」でした。中身は綺麗に入ったのですが、ユーザーから「新規ページ作成時にテンプレートとして選べない」と指摘が入ります。

調べてみると、Notion の「新規 ▾」ボタンから選べるのは **DB に紐づくネイティブテンプレート** という別概念のオブジェクトで、現行の MCP には「ネイティブテンプレートを新規作成する」API がありませんでした。Notion 画面上で空のテンプレートだけ手動で作ってもらい、その ID に対して API で中身を流し込む、というハイブリッド運用が現実解になりました。

## つまずき 2: 通常レコードとテンプレートの ID 取り違え

次にやらかしたのが、書き込み先 ID の取り違えです。

手動で作ってもらったネイティブテンプレートの ID と、似たタイミングで作成された通常レコードの ID が、末尾数文字しか違いませんでした。Claude Code が一見正しそうな ID に向けて `replace_content` を投げた結果、**テンプレートではなく稼働 DB のレコード側に本文が入る**という事故が発生。

教訓は単純で、API でテンプレートを触るときは「これは本当にテンプレートか」を `retrieve` で 1 回確認してから書き込むこと。`parent` の型 (`database_id` か、テンプレートを示す内部フラグか) を都度チェックする一手間を惜しまない方が、後片付け (API では削除できないのでユーザーに手動削除を依頼することになる) より圧倒的に安いです。

## つまずき 3: `insert_content` と Markdown の相性

中身の流し込みでは、最初に `insert_content` を使ったところ、改行と HTML テーブル・トグルがそのまま生テキストとして展開され、見た目が崩壊しました。`replace_content` で同じ Markdown を投げ直したら綺麗に反映されたので、**ブロック構造を含むコンテンツは差し替え系 API に寄せる**のが安全という結論になりました。

挿入系はカーソル位置に文字列をねじ込むイメージ、差し替え系はページ全体を Markdown として再パースするイメージ、と捉えると違いが腑に落ちます。

## 学び: ドキュメント標準化は「器」と「中身」を分けて進める

今回の一連の作業を振り返ると、ドキュメント標準化は次の 2 層で考えると整理しやすいと感じました。

- **器の層**: DB プロパティ、ネイティブテンプレート、ビュー。ここは共有資産なので破壊的変更を避け、追加のみで進める
- **中身の層**: 各ページの本文。ここは API で繰り返し書き換えられるので、テンプレートを育てながら反復していい

器を慎重に、中身は大胆に。混ぜると今回のような取り違え事故が起きます。

## まとめ

- Notion のネイティブテンプレートは API で新規作成できないので、空の器だけ手動で用意してもらう運用が現実的
- 書き込み前に `retrieve` で対象が本当にテンプレートかを確認する。ID の末尾だけで判断しない
- 構造ありの Markdown は `insert_content` ではなく `replace_content` で流し込む

次は保留している DB プロパティ追加とビュー整備に進み、テンプレートと器を噛み合わせる工程に入る予定です。
