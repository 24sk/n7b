## この記事のゴール

同じリポジトリを 2 つの Claude Code セッションで同時に触っていたら、作業ツリー (git が今監視しているファイル群) に無関係な変更が同居してしまった。この記事では、そこから「自分の担当分 1 ファイルだけ」を安全に PR にする手順を書く。読み終えるころには、`git worktree` を「共有作業机の横にもう 1 台の小さな机を出す道具」として使えるようになる、はず。

今日 N7B が触っていたのは Nuxt アプリのローディングインジケーター追加という小さな UI 改善だった。ところが同じリポジトリで別のセッションがスキル判定バッジという別機能を進めており、`git status` を叩くと両方の変更が仲良く並んでいた。この状態のまま `git add .` すると、動作確認していない他人の WIP まで PR に混ぜてしまう。

## 状況: 1 つの机に 2 人分の書類が積まれている

整理するとこうだった。

- ブランチ `feat/skill-check-badge` は main と同一コミット (まだ push されていない)
- 作業ツリーには A: `app.vue` のローディング追加 (自分の担当) と B: バッジ機能一式 (別セッション)、さらに DB マイグレーション追加まで混在
- 両者は無関係。1 つの PR に載せると本番マージ時のリスクが跳ね上がる

困るのは、単純に `git stash` で片方を退避すると、退避側のセッションが手元のファイルを失って混乱する点。共有の机 (作業ツリー) を勝手に片付けると、隣で作業している人の書類まで消える。

## 解決: worktree でもう 1 台の机を出す

`git worktree add` は、同じリポジトリに対して別ディレクトリの作業ツリーをもう 1 つ生やせる機能。レゴで言うと、同じ基礎板の上に別のプレートを追加して、そちらで組み立てを続けるイメージに近い。共有の `.git` を使いながら、ファイル操作は完全に別ディレクトリなので、隣のセッションを一切邪魔しない。

手順はこう進めた。

```bash
# origin/main の最新から新しい作業ツリーを生やす
git worktree add ../sukedachi-loading -b feat/ui-loading-indicator origin/main

cd ../sukedachi-loading
# app.vue にだけローディング変更を書き直す
$EDITOR app/app.vue

git add app/app.vue
git commit -m "feat(ui): ページ遷移中の進捗バーを追加"
git push -u origin feat/ui-loading-indicator
```

ポイントは 3 つ。

1. **base を `origin/main` にする** — 手元のブランチではなく、リモートの main を起点にすることで、混在している WIP を確実に含めない
2. **push は `-u` で新ブランチを明示** — 既存ブランチの upstream 設定が残っていて、うっかり main へ直 push する事故を防ぐ
3. **変更は 1 ファイルだけコミット** — `git status` を見て、意図したファイル以外がステージに乗っていないか毎回確認する

この後は PR を作り、CI 通過を条件にした auto-merge (squash) を設定して、本番反映まで自動で進めた。実機で `NuxtLoadingIndicator` の DOM とグラデーション色を確認して着地。

## 学び: 並行セッション時代の作法

並行して AI エージェントに作業させる運用が普通になってくると、「作業ツリーは共有資源」という前提を強く意識する必要があると感じた。今日ハマった具体的な落とし穴はこれ。

- 途中で別セッションが `git stash` を勝手に pop していて、作業ツリーの状態が数分単位で変わっていた
- `_journal.json` (drizzle のマイグレーション台帳) を古い stash から復元してしまい、一時的にファイル実体と台帳が食い違った
- `.env` は保護フックで読めない設計だったので、接続先が本番か開発かを目視確認できず、マイグレーション適用前に神経を使った

対策として今後は、複数セッションを同時に走らせるときは最初から worktree を分ける前提で始めるのが良さそう。共有の机で作業を始めてから分離するのは、書類がすでに積み重なっているぶん手数が増える。

## まとめ

- 並行セッションで作業ツリーが混ざったら、`git worktree add -b <新ブランチ> origin/main` で切り出すのが安全
- push は `-u` で新ブランチを明示し、base を `origin/main` に固定して WIP の混入を防ぐ
- マイグレーション台帳など「台帳ファイル」は stash 経由で復元しない (実体との整合が壊れる)
