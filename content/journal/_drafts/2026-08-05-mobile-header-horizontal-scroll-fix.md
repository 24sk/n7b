## この記事のゴール

モバイル (幅 375px) でページ全体が横スクロールしてしまう。原因はグローバルヘッダーだった、というよくある不具合を今日一件片付けました。本記事では「要素を減らさずに畳む」という直し方と、`scrollWidth` を実測して境界を決めるやり方を書きます。同じ症状に遭遇した Web エンジニアが、修正の判断軸を持ち帰れる内容を目指します。

結論を先に言うと、直しどころは 3 つでした。

1. 狭い幅でヘッダーの左右余白と要素間の gap を詰める
2. 文字ラベル付きボタンを「アイコンのみの円形ボタン」に切り替える
3. ラベルを戻す境界を実測で決める (今回は `sm` = 640px)

## 何が起きていたか

再現条件は `http://localhost:3000/articles` を Chrome DevTools で 375px 表示。`document.documentElement.clientWidth` は 375 なのに、`scrollWidth` は 554。つまり 179px はみ出しています。

犯人は header 内の `<nav class="ml-auto flex flex-none items-center gap-4 sm:gap-5">` でした。この nav は `flex-none` (縮まない) を持ったまま、中に「メニュー」「アップロード」ボタンや通知ベル、検索バーなどを詰め込んでいた。狭い幅では中身が nav の外にはみ出し、ページ全体を押し広げていたわけです。

満員電車の中で全員が肘を張ったまま立とうとしている状態、と言うと近い。誰かが体を斜めにするか、荷物を頭上に上げないと、そもそもドアが閉まりません。

## 「消す」ではなく「畳む」

こういうときの安易な解決策は「モバイルではボタンを `hidden` にする」ですが、ユーザーが機能にたどり着けなくなります。今回選んだのは畳む方針でした。

- 狭い幅ではヘッダーの `px-6` を `px-4` に、`gap-4` を `gap-3` に、nav 内は `gap-1.5` まで詰める
- 「メニュー」ボタン → ハンバーガーアイコンだけの円形ボタン
- 「アップロード」ボタン → プラスアイコンだけの円形ボタン
- どちらも `aria-label` を付けて、支援技術上の名前は変えない

文字ラベルを戻す境界は最初 `md` (768px) にしてみたのですが、640px 付近で検索バーが 36px に潰れる別の問題が出た。境界は `sm` (640px) に戻し、そこから上ではラベルを表示するように調整しました。

## 「境界は勘で決めない」という学び

今日いちばんの学びは、ブレークポイントを勘で置かないことでした。修正のたびに DevTools で 320 / 375 / 390 / 640 / 767 / 768 の各幅を開き、`document.documentElement.scrollWidth === clientWidth` が成立するかを実測しています。

```js
// DevTools の Console で 1 行
({ cw: document.documentElement.clientWidth,
   sw: document.documentElement.scrollWidth })
```

この 2 値が一致していれば横スクロールは発生しません。デザインカンプ上ではきれいに見えても、実測で 1px でも `scrollWidth` が上回っていれば負けです。逆に、この 1 行だけを判定条件にすれば「直った / 直っていない」を機械的に決められます。

つまずいたのは、ラベル復帰の境界を `md` に置いたときの検索バー潰れです。片方の症状だけ見て境界を動かすと、別の幅で新しい破綻が生まれる。全幅を一通りなめてから境界を決める、という手順が結局いちばん早い道でした。

## まとめ

- モバイル横スクロールは `scrollWidth` と `clientWidth` の差分を Console で実測すれば、原因要素までまっすぐたどれる
- ヘッダーの機能は消さず、ラベルを畳んでアイコン化 + `aria-label` でアクセシビリティを保つ
- ブレークポイントは勘で置かず、複数幅を実測してから確定する

次に別プロジェクトで同種の不具合を踏んだら、まず Console の 1 行から入ります。
