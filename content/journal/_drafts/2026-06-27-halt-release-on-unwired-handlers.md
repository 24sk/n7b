## 「リリースまで一気に」と頼んだら、途中で止まった

この記事は、Claude Code に「現在の変更をステージング → コミット → プッシュ → リリース」と一気通貫で頼んだら、**直前で勝手に止められた**話です。読むと次のことが分かります。

- なぜエージェントは「コミット前に止まる」べきだったのか
- 未配線のハンドラ (定義したのに繋いでいない関数) を検知する仕組み
- lint と型チェックを「品質ゲート」として置く意味

結論を先に置きます。**ビルドが通らない変更を main に乗せないための一番安いセーフティネットは、`unused-vars` を error にした lint**。今日それが体を張って止めてくれました。

## 起きたこと: 「未完成のまま」コミット直前

あるプロジェクトで、記事エディタに「⌘+S で保存」「公開時に確認ダイアログを出す」という UX を足していました。チャット側にも記事カードを描画する変更が混ざっていました。

この状態で「コミットしてプッシュしてリリースまで」と依頼。Claude Code は素直に作業を始めましたが、`git diff` を読み込んだ段階で違和感に気づきます。

- `toArticleResult` という関数が呼ばれているのに、**どこにも定義がない**
- 公開確認ダイアログ用の `onPublishClick` / `confirmPublish` が **定義されているのに使われていない**
- 記事カードのコンポーネントを作ったのに、**親コンポーネントから一切 import されていない**

つまり「半分だけ書いて、配線を忘れた」状態。このまま `main` に乗れば、チャット画面はランタイムエラーで落ち、公開ボタンは沈黙します。

ここでエージェントは型チェックと lint を走らせて、`'onPublishClick' is defined but never used` を確認。そして **「コミット・リリースを止めて報告します」** と返してきました。

## なぜ止められたのか: ESLint の `no-unused-vars` が効いた

面白いのは、止められた根拠が高度な解析ではなく、**ESLint の素朴な未使用変数チェック**だったところです。

レゴで例えるなら、「箱から出したのに、組み立て図のどこにも貼られていないブロック」を検知している状態。コードのロジックを理解しなくても、「定義したのに参照ゼロ」という事実だけで未完成を炙り出せます。

このリポジトリでは `pre-commit` フックで lint を走らせていたので、仮にエージェントが気づかず `git commit` を叩いても、Husky 層で弾かれる二段構えになっていました。

まとめると、止められた理由はこの 3 つの重なりです。

1. `unused-vars` を warning ではなく **error** にしてある
2. `pre-commit` で lint がブロッキングで走る
3. エージェントが「コミット前に lint と型チェックを通す」を手順に組み込んでいる

どれか 1 つでも欠けると、未配線のまま `main` に届く可能性がありました。

## つまずきポイント: 「Done」の定義をエージェントと揃える

今日の体験で見えてきた落とし穴は、人間側の「完成」とエージェント側の「完成」がズレやすいことです。

人間は「だいたい書いた、あとは流すだけ」のつもりでも、エージェントから見ると「定義はあるが配線されていない関数」が残っている。逆にエージェントに「リリースまで」と渡すと、配線抜けを自分で見つけて埋めようとします (実際この後、未配線の 3 点を実装し直して、lint・テスト 125 件・型チェックが全部緑になってからリリースまで進めました)。

ここで重要なのは、**「コミット前に lint と型を通す」を依頼文ではなく仕組みに埋める**こと。エージェントの善意に頼ると、急ぐ場面でスキップされます。`pre-commit` と CI の二段ゲートに任せるのが結局いちばん落ち着きます。

もう一つの学びは、`unused-vars` を厳しめに保つ価値。「あとで使うから残しておく」を許すと、未配線のハンドラと区別がつかなくなります。残したいときだけ明示的に `// eslint-disable-next-line` を書く方が、未完成コードの自然な検知装置として働きます。

## まとめ

- ビルドを壊さない最後の砦は、`unused-vars` を error にした lint と `pre-commit` フックの組み合わせ
- 「リリースまで一気に」と頼むときほど、品質ゲートを依頼文ではなく仕組みに置く
- エージェントが「止めて報告します」と言える設計のほうが、結果的に速い
