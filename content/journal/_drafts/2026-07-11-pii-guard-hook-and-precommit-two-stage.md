## この記事で分かること

電話番号やメールアドレス、クレジットカード番号といった PII (個人情報) がリポジトリに紛れ込むのを、開発フローのどこで止めるか。今日 N7B が組み込んだのは「編集した瞬間」と「コミットする瞬間」の二段構えのガードです。この記事では、既存の機密スキャンの仕組みを再利用しながら、Claude Code の hook と Husky の pre-commit に PII 検知を挟み込んだ手順と、落とし穴を書き残します。

読み終わると次の 3 つが持ち帰れます。二段で止める設計の考え方、パターンを共有モジュール化する意味、そして pre-commit で本当にコミットがブロックされることの確認方法です。

## なぜ「二段」なのか

ガードが 1 段だと、抜け道は必ず生まれます。編集時の hook だけだと、hook を無効化した状態でコミットされた瞬間に素通り。pre-commit だけだと、ローカルで書きかけたコードが AI エージェントを介して外部にコピーされる可能性が残る。

イメージとしては、玄関と勝手口の両方に鍵をかけるのに近い体感です。片方だけだと、もう片方から入られる。だから編集の瞬間 (hook) と、履歴に刻まれる直前 (pre-commit) の両方に検問を置きました。

- **一段目**: Claude Code の `PostToolUse` hook で、ファイル書き込み直後にスキャン
- **二段目**: Husky の `pre-commit` で、ステージ済みファイルをまとめてスキャン

## 実装で一番効いたのは「パターンの共有化」

最初に手を動かしたのは、既存のアップロード時スキャン (`secret-scan.ts`) にあった正規表現パターンを、`shared/scan-patterns.ts` という Nuxt 非依存のモジュールへ抽出することでした。

理由はシンプルで、同じルールを 3 か所 (アップロード / hook / pre-commit) に散らばらせたくなかったから。パターンが 3 つに分裂すると、片方だけ更新されて片方が古いままになる事故が必ず起きます。レゴブロックで例えると、色の定義ブロックを 1 個だけ作って、必要な場所で同じブロックを差し込む形にしたイメージです。

共有化のあとは、CLI スクリプト `scripts/scan-secrets.ts` を Node 24 の TS 直実行で書きました。tsx などの追加依存を入れずに済んだのは、既に `db:seed` で同じ実行方式が使われていたから。pre-commit は起動が速いほど開発体験を壊さないので、依存を増やさないのは地味に効きます。

### hook 側

`.claude/settings.json` の `PostToolUse` に CLI 呼び出しを登録し、Write / Edit の直後に走らせる形にしました。exit code が非ゼロなら Claude Code 側で差し戻される流れです。

### pre-commit 側

`.husky/pre-commit` で lint-staged と並べて CLI を呼びます。ステージ済みファイルのみを対象にすることで、リポジトリ全体を走査する重さを避けました。

## 落とし穴: 「本当にブロックされるか」を実地で試す

ガードを書いた直後、いちばん怖いのは「書いたつもりで動いていない」パターンです。今日は最後に、テストコードで検証するだけでなく、実際に PII を含むファイルをステージしてコミットしてみました。

結果、`husky - pre-commit script failed` でコミットが止まり、git log は前のコミットのまま。これで「机上ではなく現場でブロックできる」が確認できました。プレースホルダ (例: `test@example.com` のようなダミー) は誤検知しないよう除外リストで抜いてあり、自分の変更自身をスキャンしても通ることを確かめてから push しています。

もう一つ小さな学びは、Luhn チェックを入れたクレジットカード番号の検知が思ったより効いたこと。単純な桁数マッチだと GitHub の Issue 番号やハッシュを誤検知しますが、Luhn を通すと現実的な誤検知率まで下がりました。

## まとめ

- PII/機密の混入は「編集時 hook」と「pre-commit」の二段で止めると、片方が外れても守れる
- スキャンパターンは 1 か所に集約し、CLI 経由でどこからでも同じルールを呼ぶ
- ガードを書いたら必ず「実際に PII を含むコミットが止まる」ところまで実地確認する

次は E2E テストで、hook が無効化された状況下でも pre-commit が最後の砦として機能するシナリオを追加していきます。
